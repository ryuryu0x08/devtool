# 工具箱 · Toolbox

面向开发者的跨端（PC + 移动端）工具箱，按 Claude Design 交付的高保真原型（`design/project/Toolbox.dc.html`，1a 经典侧栏方向）实现。

## 产品原则

1. **操作路径最短**：用户想做一件事时，从打开页面到拿到结果，操作步骤要尽可能少。
2. **不悄悄改动数据**：格式化、转换、对比、编码都不能悄悄改变数据；不支持的情况要说明原因。

两条冲突时以第 2 条为准。比如可以按内容自动判断用户的意图，但判断结果必须显示出来，并且一次点击就能改回。

新增或修改功能时，先数一数完成最常见的那件事要几步，看能不能再少一步，再对照下面的约定检查。

### 1. 操作路径最短：具体约定

**打开就能输入。** 桌面端切换到工具后，光标已经在主输入框里，不用先点一下输入框。如果用户已经点进了别的输入框，光标不会被抢走。

**结果随输入出现。** 没有"转换""计算""生成"按钮。

**点了就有反应。** 需要时间的操作会立即显示正在进行，不让用户以为没点上，比如复制图片、计算大文件的哈希（带进度）、处理大段输入。

**点结果就复制，而且只有这一种方式。** 结果本身就是复制按钮，旁边不再放"复制"按钮或"复制"字样，避免同一件事出现两个入口。鼠标移上去整块高亮，停留时提示"点击复制"，复制后显示"已复制"。
- **单个值**：点这一行的任何位置都复制。包括时间戳页的全部结果、顶部"现在"一栏、哈希值、差异清单里的路径、识别出的二维码内容。
- **二维码图片**：点二维码复制图片。
- **大段结果文本**（Base64 的结果、格式化的"文本"视图）：点一下复制全部；拖动可以只选中其中一部分，再用 ⌘C / Ctrl C 复制选中的部分。Base64 的十六进制视图点一下复制的是不带空格和偏移的十六进制字符串。

一个例外：格式化默认的"结构"视图里，每一行有"路径"和"值"两种内容，点一行是选中它，再选择复制路径还是值。所以复制整个格式化结果用工具栏的"复制结果"，它在两种视图里都可用。

**在哪儿粘贴都行。** 在页面空白处按 ⌘V / Ctrl V。当前工具能用这段内容，就留在当前工具：

| 当前工具 | 粘贴的内容 | 结果 |
|---|---|---|
| 生成二维码 | 任意文本 | 填入内容 |
| JSON 对比 | JSON / TOML | 填入最近没有编辑过的一侧：连续粘贴两次，依次填入 A 和 B |
| Base64 | 任意文本 | 填入输入框。Base64 或 data URL 自动切到"解码"，其他文本切到"编码"，切换时有提示 |
| 哈希 | 哈希值（已有文本或文件时） | 填入"核对"，已加载的文件保留 |
| 哈希 | 其他文本 | 作为要计算哈希的文本 |

否则按内容打开对应的工具：

| 粘贴的内容 | 打开 |
|---|---|
| 时间戳、日期时间 | 时间戳转换 |
| JSON / TOML | 对应的格式化 |
| Base64、data URL | Base64（解码） |
| 图片 | 识别二维码 |
| 其他文本 | 生成二维码 |

往空的 Base64 输入框里粘贴时，也按同样的规则选择方向。往已有内容里继续粘贴，不会改变方向。

判断 Base64 的依据：data URL，或者能完整解码成可读 UTF-8 文本（或已知文件类型）的 Base64。普通单词不会被误判：10 万个 8–19 位的随机字母数字串里，没有一个被判成 Base64。

**拖入文件。**

| 当前工具 | 拖入 | 结果 |
|---|---|---|
| Base64、哈希 | 任意文件（一次一个） | 按文件原样处理。Base64 在"解码"模式下，内容是 Base64 的文本文件会填入输入框，其他文件改为编码 |
| JSON 对比 | 一个 .json / .toml | 填入下一侧 |
| JSON 对比 | 两个 .json / .toml | 分别填入 A 和 B |
| 其他工具 | 图片 | 识别二维码 |
| 其他工具 | .json / .toml | 对应的格式化 |
| 其他工具 | .txt | 和粘贴同样的规则 |

**用撤销代替确认。** 会替换已有内容的操作（示例、清空、格式转换、粘贴、拖入文件）直接执行，提示里有"撤销"，被替换的文件也能恢复。没有"确定要清空吗？"这类确认框。

**自动判断，但显示出来。** 时间戳的单位、Base64 的方向、对比填入哪一侧，都由内容决定。判断结果写在界面或提示里，改回只要一次点击。

**键盘。**
- ⌘K / Ctrl K 或 `/` 搜索工具，支持中文、英文和拼音首字母，Enter 打开。在搜索框里粘贴内容，第一项就是"用对应工具处理"。
- ⌘B 收起侧栏。
- 时间输入框里按 ↑ ↓ 调整光标所在的那一段。

### 2. 不悄悄改动数据：具体保证

- **格式化**只改变空白和缩进：JSON 的每个记号（数字、字符串转义、重复键）、TOML 的每个值的原始写法和每条注释都原样输出。输出前会重新解析并逐项校验，校验不通过就报错，不输出。
- **JSON ⇄ TOML 转换**遇到目标格式无法精确表示的值（超出 64 位的整数、超出双精度的小数、`null`、`nan` / `inf`、重复键）会拒绝转换并指出位置；日期时间转成 JSON 字符串时会提示。
- **差异对比**按精确的十进制值比较数字；两边都是 TOML 时区分整数和浮点数；值相同但写法不同（如 `1.0` 与 `1`、`0xFF` 与 `255`）单独标为"写法不同"。看起来相近的修改会注明原因：类型变化（如 TOML 的 `1` → `1.0` 是整数 → 浮点数，`"1979-05-27"` → `1979-05-27` 是字符串 → 日期），或"同一时刻，时区偏移不同"。值里的换行和连续空格按原样显示。
- **时间戳**保留毫秒以下的精度（微秒、纳秒）；夏令时切换导致某个本地时间出现两次或不存在时会提示。1900 年前后各地使用的地方平时（如上海 +08:05:43）按秒显示偏移，ISO 文本解析回去是同一时刻。全角数字（中文输入法全角模式）可以识别。
- **二维码识别**自行解码原始字节（UTF-8、GB18030、Shift_JIS），不是 UTF-8 时标明所用编码；无法按 UTF-8 编码的文本不会生成二维码。
- **复制**：内容含 NUL 或孤立代理字符（系统剪贴板可能改动）时会提示，"复制值"改为复制转义写法。
- **Base64 / 哈希**：文本按 UTF-8 编码，含孤立代理字符（没有 UTF-8 形式）时拒绝，不会替换成 U+FFFD。浏览器输入框会把 CRLF 换行转成 LF，粘贴的内容含 CRLF 时会提示，可以选择按 CRLF 计算，或直接拖入文件按原样计算。解码时容忍的写法（空白换行、缺少补齐、URL 安全字符集、data URL 前缀、最后一个字符的多余位）都会列出；无法解码时指出位置。MD5、SHA-1、SHA-256 是自己实现的（浏览器自带的 Web Crypto 没有 MD5，且非 HTTPS 页面不可用），测试中与 Node 的 `crypto` 逐一比对。
- **不会丢输入**：替换已有内容的操作都能撤销（见上文）。
- **显示如实**：不可见字符和文字方向控制字符（如 U+202E）在结果、路径、错误信息和提示中标出（复制时仍是原字符）；语法错误在出错的那一行里直接标出出错的字符；极大的差异结果分段显示并注明总数。
- **本地保存**：输入过大存不下时会提示，并删除旧副本，避免刷新后看到过期内容。超过 4 万字符的输入在停止输入后才处理，处理中不能复制或转换。

## 功能

- **时间戳转换**：秒 / 毫秒 / 微秒 / 纳秒自动识别；时区可搜索切换，默认本机时区，记住上次选择与最近使用；时间输入支持 `2026-10-26 14:30`、`明天 9点`、`下午3点半`、`10/26 9:00`、`now` 等写法，↑↓ 逐段调整，快捷按钮 ±1 时 / ±1 天。
- **生成二维码**：实时生成，支持中文，容错等级 L/M/Q/H；点二维码复制图片，也可下载 PNG。
- **识别二维码**：粘贴、拖入或选择图片，一图多码并在图上标号；点识别出的内容复制，多个码可一次复制全部；图片仅在本地处理。
- **JSON / TOML 格式化**：结构视图可折叠、按层级折叠，选中一行后复制路径或值；缩进、按 key 排序、压缩复制、JSON ⇄ TOML 互转；错误定位到行列。
- **JSON 对比**：语义对比（忽略 key 顺序和空白），可忽略数组顺序、仅显示差异，合并视图 / 差异清单；也支持 TOML 输入。
- **Base64**：文本或任意文件编码（标准 / URL 安全字符集，可选补齐，文件可输出 data URL）；解码 Base64 或 data URL，文本直接显示，二进制以十六进制显示并可下载，图片可预览。
- **哈希**：同时算出 MD5、SHA-1、SHA-256（十六进制大小写或 Base64）；文本按 UTF-8 计算，文件按原样分块计算（大文件不卡页面）；可粘贴期望值核对，支持十六进制、Base64（如 SRI 的 `sha256-…`）和 `sha256sum` 输出的一行。
- **全局**：中英切换；浅色 / 深色 / 跟随系统；输入与偏好保存在本地。

所有依赖（字体、二维码、TOML 解析）都打包在本地，可离线使用。

## 开发

```bash
npm install
npm run dev            # 本地开发
npm run build          # 类型检查 + 构建到 dist/
npm test               # 单元测试、随机化测试、TOML / JSON 一致性测试集
npm run test:e2e       # 浏览器端到端测试（Chromium，针对构建产物）
npm run test:mutation  # 植入错误测试：检验上面的测试能否发现已知类型的错误
npm run typecheck      # 应用与端到端测试代码的类型检查
npm run test:all       # typecheck + test + test:e2e
```

新机器第一次跑端到端测试前需要 `npx playwright install chromium`。

构建产物是纯静态文件（`base: './'`），可部署到任意静态托管。

### 测试

- **单元测试**：`src/lib/data.test.ts`（格式化、转换、差异对比的用例矩阵，含 JSON ⇄ TOML 交叉用例）、`src/lib/time.test.ts`（含所有时区的 ISO 往返）、`src/lib/hash.test.ts`（MD5 / SHA-1 / SHA-256 与 Node 的 `crypto`、Base64 与 `Buffer` 比对，含公开测试向量、各种长度和任意分块；以及粘贴内容的意图判断）、`src/i18n.test.ts`（中英文案的键和占位符一致，每处调用都填全了占位符）。
- **随机化测试**：`src/lib/fuzz.test.ts`（解析器与 `JSON.parse` 判断一致、格式化无损且稳定、篡改必被校验发现、差异结果可还原两侧）。
- **一致性测试集**：TOML 官方测试集（`test/toml-test`，来自 [toml-lang/toml-test](https://github.com/toml-lang/toml-test)）和 JSONTestSuite（`test/json-test-suite`，来自 [nst/JSONTestSuite](https://github.com/nst/JSONTestSuite)），均为 MIT 许可。
- **端到端测试**（`e2e/`，Playwright + Chromium，针对构建产物）：
  - 外壳与布局，含 320 / 390 / 1280 宽度；
  - 智能粘贴与拖放、撤销、本地保存、复制失败；
  - 时间戳与夏令时；
  - 二维码"生成 → 下载 → 识别"往返，含 GBK 和一图多码；
  - JSON / TOML 格式化与转换；
  - 差异对比的用例矩阵与跨工具往返；
  - Base64 与哈希，含 24 MB 文件、CRLF 粘贴、核对；
  - `e2e/shortest-path.spec.ts` 逐条检查上面"操作路径最短"的约定。

  每个测试都会检查：页面无报错，界面上没有未填的占位符、`undefined`、`NaN`。
- **植入错误测试**（`scripts/mutation.mjs`）：逐个植入 68 种已知错误，每一个都必须让测试失败。例如数字按双精度比较、漏报新增字段、偏移按分钟取整、哈希常量写错、超过 512 MB 的长度溢出、Base64 混用字符集未报错、焦点被抢走、长提示超出屏幕、结果行点击不复制、粘贴总是填入对比的 A 侧、被替换的文件无法撤销。

## 目录

```
src/
  App.tsx              应用外壳：全局快捷键、粘贴与拖放的去向、撤销、持久化
  store.tsx            状态定义、localStorage 读写、Context
  i18n.ts              工具注册表、分类与中英文文案（新增工具从这里开始）
  components/          侧栏 / 移动端顶栏、命令面板、分段控件、点击即复制的结果行和结果文本块（Kv.tsx）、Logo
  tools/               各工具页面
  lib/                 时间解析、数据对比、二维码、Base64、哈希等纯函数
e2e/                   端到端测试（fixtures/ 下是生成测试图片的脚本和图片）
scripts/mutation.mjs   植入错误测试
scripts/icons.mjs      由 public/favicon.svg 生成 apple-touch-icon.png（改了图标后运行）

```

### 新增工具

1. 在 `src/i18n.ts` 的 `TOOLS` 中添加一项（`id`、分类、图标、中英文名称、搜索关键词）；新分类同时加到 `CATS` 和 `CAT_ORDER`。
2. 在 `src/tools/` 下实现组件，通过 `useApp()` 读取状态和文案。单个结果值用 `Kv`，大段结果文本用 `CopyBlock`（都在 `components/Kv.tsx`），点击即复制，不要再另放复制按钮。
3. 在 `src/App.tsx` 中按 `S.tool` 渲染该组件。如果这个工具能直接使用粘贴的文本或拖入的文件，在 `takeText` / `handleFiles` 里加上它的规则，并更新上面的表格。
4. 对照"产品原则"检查：最常见的任务要几步，能不能少一步；有没有悄悄改动数据的地方。在 `e2e/` 中为新约定加测试。
